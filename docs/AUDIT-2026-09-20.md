# Project audit — 2026-09-20

> Follow-up: the repository-wide Markdown refresh addressed documentation finding A15 (CLI installation and license inventory). The findings below preserve the original audit evidence. No production-code fixes or package version changes were made by that refresh.

## Scope and conclusion

Repository-wide review of the 14 package manifests, core/CLI/MCP/VS Code
integration, rendering and export paths, development server, watchers, PHP
runtime and library boundaries, plugins, browser helpers, publishing, and
project documentation. This is an audit of the current working tree, not a
certification that every behavior or upstream binary is correct.

The current tree has release-blocking defects in export safety, project
creation, PHP configuration reload, minimal rendering, and extension packaging.
Seven P1 findings, nine P2 findings, and two P3 findings are listed below.
P1 means fix before release; P2 means a functional/security or verification gap
to address next; P3 means lower-impact robustness or packaging debt.

Existing modifications to the PHP loader/WASM, `docs/ROADMAP-FUTURE.md`, and
`jspi/php.js.bak` were preserved. Findings involving PHP reflect those local
binaries. Production source code was not changed by this audit.

## Findings

### A01 — P1: Export can delete the source project

**Resolved after the audit:** overlapping paths, including symlink/junction aliases and missing output descendants, are rejected before deletion. `Project.export()` also checks before triggers/rendering. Regression coverage: `packages/kirigami/test/dist.test.js`.

**Reproduced.** `packages/kirigami/bin/tasks/dist.js:20` calls `emptyDir()`
before copying, and its validator is empty. `Project.export()` accepts a path
override without checking its relationship to `config.root`.

Calling the dist task with the same disposable directory as source and
destination deleted `sentinel.txt`, then returned `{ success: true, files: [] }`.
A destination that is an ancestor of the source can also remove the source;
a destination nested inside it risks recursive copying. The latter two cases
follow from the code and were not executed.

**Fix:** Resolve and validate source/destination relationships before any write,
including filesystem roots, project/config directories, and symlink aliases.
Reject overlapping trees and test these cases with disposable fixtures.

### A02 — P1: Export copies PHP sources and hidden-directory contents

**Resolved after the audit:** `.php` files and dot-prefixed directories are excluded, alongside the existing filters. Public assets and explicit ignore rules are covered by export regression tests. Other private content still needs project-specific ignore rules.

**Reproduced.** `packages/kirigami/bin/tasks/dist.js:59` excludes dot-prefixed
file basenames but not `.php`; the directory branch at line 94 excludes only
underscore-prefixed directories. The fixture exported both `helper.php` and
`.private/data.txt`. The function named `loadGitignore()` does not read a
`.gitignore`; only configured `export.ignore` patterns are used.

**Impact:** Source/configuration data can enter a public static deployment when
present under the source root. Exclude server source extensions and private
directories by default, with explicit handling for public `.well-known` content.

### A03 — P1: PHP HTTP helpers explicitly disable TLS verification

**Resolved after the audit:** both helpers now set `CURLOPT_SSL_VERIFYPEER` to `true` and `CURLOPT_SSL_VERIFYHOST` to `2`. `getInfo()` returns `false` on cURL failure. A local HTTPS fixture verifies accepted/rejected certificates, hostname checks, redirects, and downloads under native PHP; the WASM CA bundle and ini settings are checked separately. End-to-end HTTPS in the current working-tree WASM binary remains unverified because requests time out before reaching its proxy; see [BUGS.md](BUGS.md).

**Confirmed by code.** `packages/php-prepros/src/libraries/curl.class.php:62`
and line 84 set both `CURLOPT_SSL_VERIFYPEER` and `CURLOPT_SSL_VERIFYHOST` to
false in `getInfo()` and `getContents()`. This bypasses the CA bundle installed
by `packages/php-wasm/runtime/runtime.js`.

**Impact:** HTTPS-fetched pages, assets and cookies lack normal peer/hostname
verification. Enable peer verification and hostname verification (`2`), using
the existing CA bundle. Add an invalid-certificate rejection check. No live
interception test was performed.

### A04 — P2: Plugin installation interpolates input into a shell command

**Resolved after the audit:** installation validates the complete input batch as registry plugin names before any lookup or install, validates registry version strings, and invokes npm with an argument array and `shell: false`. Windows runs `npm-cli.js` through Node instead of invoking `npm.cmd`. Eight regression tests cover unsafe input, shorthand/scoped names, offline fallback, registry metadata, save flags, npm discovery, and real Windows argument delivery through paths containing spaces and shell characters. No registry packages were installed during verification.

**Confirmed by code.** `packages/cli/bin/cmd/install.js:11` accepts arbitrary
non-slash suffixes, including shell metacharacters, and line 107 interpolates
the resulting specification into `execSync('npm install ...')`. A matching
full name is retained even when registry lookup fails.

**Impact:** A crafted plugin argument can become shell syntax. This requires
control of the CLI argument; it is not evidence of remote unauthenticated
execution. Use strict package-spec validation and an argument-based subprocess
invocation, including a Windows-safe npm entry point. No injected command was run.

### A05 — P1: Starter package generation is broken after the CLI split

**Resolved after the audit:** starter manifests now include `@kirigami/cli`, core, and Canva, each using its own installed manifest version. Canva exposes its manifest through a package export; resolution starts from core so nested dependencies work. Starter banners are copied from core's installed assets. Four regression tests cover generated dependencies, banner preservation, an isolated nested package layout, and the real create command with local template archives (missing starter files, complete templates, and existing projects). GitHub downloads and npm installation were not exercised.

**Confirmed by evaluating the manifest-derived values.**
`packages/cli/bin/cmd/create.js:440` reads the CLI manifest but treats its version
and dependencies as the core manifest. It emits:

```json
{
  "@kirigami/kirigami": "^0.1.0",
  "@kirigami/canva": "^undefined"
}
```

It also omits `@kirigami/cli`, the package that now owns the `kiri` executable.
This affects templates without a `package.json`; a full network-based scaffold
was not run. The starter banner path also still points into CLI `assets/`,
although the banner resides in the core package.

**Fix:** Derive each dependency from its actual package manifest, include the
CLI, and resolve the banner from the core package. Test a template without
either starter file in an isolated install.

### A06 — P1: Project reload leaves the PHP configuration and plugin list stale

**Resolved after the audit:** `Project.reload()` invalidates the PHP configuration/runtime and plugin include list before loading the new configuration and registering plugins. PHP-prepros owns a disposable runtime, serializes its PHP operations and resets, and initializes a fresh filesystem/network mode on next use. An empty plugin include list clears the previous list. Real WASM regression checks cover repeated builds, changed data/root/mount extensions, deleted files, plugin disable/re-enable/include changes, network mode changes, queued resets, and recovery after failure. Runtime lifecycle tests verify singleton isolation and network proxy/socket shutdown. Whole-project concurrent operations and hot replacement of cached JavaScript plugin modules remain outside this fix.

**Reproduced for configuration; plugin cache confirmed by code.**
`packages/kirigami/index.js:84` resets the core config and JS hooks, but
`packages/php-prepros/src/prepros.js:24` caches its own config and runtime.
`packages/kirigami/bin/tasks/prepros.js:15` also permanently caches PHP includes.

After rendering `$project` as `Before`, changing YAML to `After` and calling
`reload()` changed `project.config.kirigami.project` to `After`, while a successful
rebuild still rendered `Before`. This affects long-lived API, MCP and extension
sessions. Disabling a PHP-contributing plugin can likewise leave cached includes.

**Fix:** Give reload a coordinated invalidation path for PHP configuration,
mounts/runtime state and plugin includes. Verify repeated builds and plugin
enable/disable transitions, not just a fresh process.

### A07 — P1: Optional layout fields produce warnings inside generated HTML

**Reproduced.** With valid `prepros: {}` and a simple `_index.php`,
`packages/php-prepros/src/libraries/prepros.class.php:54` and line 85 read absent
`before`/`after` properties. Four `Undefined property` warnings become page
content because output buffering and `display_errors` capture them.

Build and export both reported success and their top-level results did not
surface these warnings. Default absent properties before invoking hooks/includes
and propagate rendering diagnostics through the aggregate prepros task result.

### A08 — P1: The compiled VS Code extension cannot resolve core resources

**Reproduced with a stub host, not real VS Code.** The build passes, but
`packages/vscode/esbuild.mjs:50` substitutes the bundle URL for all
`import.meta.url` uses. The core config's `createRequire()` consequently resolves
`../kirigami.schema.json` relative to `packages/vscode/dist/extension.js`.

Activation against a valid temporary project logged:

```text
Cannot find module '../kirigami.schema.json'
Require stack:
- .../packages/vscode/dist/extension.js
```

Core task modules and banner paths are also location-dependent and need the
same packaging review. Static imports additionally capture `process.cwd()`
before `activate()` changes it. Preserve package-relative resolution, explicitly
package required resources, and verify actual activation and all commands in
the Extension Development Host. The older-host `node:sqlite` issue already in
`BUGS.md` remains a separate unverified compatibility concern.

### A09 — P2: Malformed URLs can terminate the development server process

**Reproduced.** `packages/kirigami/bin/libs/devserver.js:80` performs
`decodeURIComponent()` outside error handling. Requesting `/%ZZ` raised
`URIError: URI malformed` from the HTTP request callback.

Return 400 for malformed input. Also handle filesystem read and stream errors;
the current unhandled stream error path at line 148 can fail when a file changes
between stat and read. That filesystem race was not reproduced.

### A10 — P2: The development server exposes source files

**Reproduced.** `packages/kirigami/bin/libs/devserver.js:79` serves any existing
file under the root. `/helper.php` returned its source with status 200. Dotfiles
and underscore-prefixed sources have no dedicated denial rule either. Default
binding is loopback, so exposure broadens when the user chooses a network host.

Serve intended public assets and deny template/private files. Canonicalize real
paths to address symlink escapes; the current containment guard is lexical.
Symlink escape was not tested.

### A11 — P2: Watch mode misses new pages and deletions

**Add callback reproduced; deletion omission confirmed by code.**
`packages/kirigami/bin/tasks/prepros.js:86` returns when a batch contains only
`add` events. `packages/kirigami/bin/libs/watchengine.js:196` subscribes to `add`
and `change`, but never `unlink`/`unlinkDir`. Esbuild and Sass callbacks also
discard add-only batches.

New pages are not immediately rendered, and deleted inputs cannot trigger
cleanup or rebuilds. Handle additions/deletions and define removal of obsolete
HTML and sitemap entries.

### A12 — P2: Restarting watchers accumulates implicit prepros tasks

**Reproduced.** `buildWatchRules()` prepends to `config.tasks` in place
(`packages/kirigami/bin/libs/watchengine.js:25`). Two calls on the same config
produced one then two rules. Repeated serve/watch toggles can duplicate work
and contaminate later task listings/builds. Construct a local task list instead.

### A13 — P2: Async watcher failures have no rejection handler

**Confirmed by code.** `createWatchers()` passes async `flush` directly to
`setTimeout`; `flush` has `finally` but no `catch`. A throwing hook, callback,
or render/mount failure can become an unhandled rejection instead of a failed
build event. `Project.serve()` can leave status at `start` when its callback
throws. Catch failures at the scheduling boundary and emit a terminal failure
event. Also ensure watcher/server startup failures close acquired resources.

### A14 — P2: VS Code reports a failed PHP script as finished successfully

**Confirmed by code.** `packages/vscode/src/commands.js:61` awaits
`project.run()` but discards its structured result and always shows the finished
message unless an exception is thrown. A normal `{ success: false, error }`
result is therefore hidden. Inspect the result and log/show its diagnostic.

### A15 — P2: Public documentation describes the pre-split installation

**Confirmed against local manifests.** The root README directs users to install
`@kirigami/kirigami` to obtain `kiri`, but only `@kirigami/cli` now declares that
binary. The package table also omits several current packages. Existing TODO
already flags the core README rewrite; this finding extends to the root entry
point and executable installation instructions.

The root README and `docs/CONTEXT.md` licensing overview say everything except
PHP-WASM is MIT, while local manifests declare GPL-3.0-or-later for
`audiowaveform-wasm` and LGPL-2.1-or-later for `bestframe`. Reconcile the inventory
with those manifests. This is a metadata inconsistency, not a legal assessment.

### A16 — P2: There is no executable regression suite or repository CI gate

**Confirmed by inventory.** Six workspaces have the placeholder failing test
command, the others have no test script, and root has only release scripts.
No checked-in test/spec suite or `.github/workflows` pipeline was found.
Syntax checks and successful compilation do not catch the reproduced defects.

Add focused tests for path safety, minimal build/export, config reload, watch
events, CLI scaffolding and packaged extension resources. Exercise the declared
Node 24 floor and Windows, rather than only the local Node 26 runtime.

### A17 — P3: Local backup files are included in the publishable WASM package

**Reproduced by dry pack.** `packages/php-wasm/package.json` includes the entire
`jspi` directory. The current untracked `jspi/php.js.bak` appears in the tarball
manifest (392,661 bytes). It was preserved as existing user work.

Use a tighter file allowlist or package ignore rule and inspect tarball contents
before publishing. No package was published during this audit.

### A18 — P3: Disabled browser storage prevents oEmbed metadata loading

**Confirmed by code; browser scenario not exercised.**
`packages/plugin-embed/src/embed.js:57` reads `localStorage` before entering any
try/catch. A storage access exception rejects `getOembed()` before its network
fallback. The play button remains, but title/thumbnail metadata never loads.
Guard reads as well as writes, as the Canva theme helper already does.

## Additional follow-up and existing debt

- Existing font `ital` axis, YAML keep-chomping, missing layout-file validation,
  and old/forked VS Code compatibility questions remain open; this audit does
  not settle them.
- PHP runs share mutable VM state and `/internal/prepros_result.json`, while
  some watch callbacks use `Promise.all()` and MCP operations have no explicit
  project queue. Stress-test concurrent operations before claiming concurrency
  support; cross-request corruption was not established in this audit.
- The PHP bridge's `runenv()` containment test checks whether a relative path
  is empty, not whether it escapes the project. Review its intended trust
  contract alongside host spawn/mount capabilities; PHP templates are not an
  isolation boundary for untrusted projects.
- Browser helpers, plugins, Sass functions and multimedia wrappers were reviewed
  selectively. Full visual/accessibility, image fidelity, font, video and audio
  fixture coverage remains to be added. The compiler source repositories are
  outside this audit's scope.
- Legacy French comments still exist, including in core and Canva source. The
  new language policy applies to subsequent edits; historical content was not
  bulk-translated during this audit.

## Suggested correction order

1. Protect export paths, exclude private source files, and restore TLS verification.
2. Repair scaffolding and minimal rendering; add reproductions as regression tests.
3. Coordinate PHP/plugin reload and make watch lifecycle handling reliable.
4. Correct extension packaging and verify it inside the real host.
5. Align installation/licensing docs, tighten tarball contents, and add CI gates.

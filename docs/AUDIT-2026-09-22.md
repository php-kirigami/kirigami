## New findings

### N1 — P1: Export empties any destination that does not overlap `kirigami.root`

**Reproduced.** The A01 fix (`assertSafeExportPaths()` in
`packages/kirigami/bin/tasks/dist.js:58`) rejects only destinations that
overlap the *source root*. `emptyDir()` then deletes everything in the
destination. With `kirigami.root: src`, `project.export({ path: 'scripts' })`
deleted `scripts/deploy.php` and returned `{ success: true }`.

The same applies to `.git`, `node_modules`, the directory holding
`kirigami.yaml`'s siblings, or any absolute path. The MCP `kirigami_export`
tool passes an agent-supplied `path` straight through, so an agent's mistake
is enough to trigger it.

**Fix:** Refuse to empty a non-empty destination unless it carries a marker
written by a previous export (e.g. `.kirigami-export`). Reject destinations
that contain the project directory, and known project directories (`scripts`,
`node_modules`, `.git`, configured task sources). Consider restricting MCP
export paths to the project directory.

### N2 — P2: `validate()` drops plugin-injected tasks until the next reload

**Reproduced.** `Project.validate()` (`packages/kirigami/index.js:113`)
replaces `#config` with a freshly loaded config. That config lacks the
`tasks:register` injection that `reload()` performs, while `#loaded` stays
`true`. After validation, `tasks`, `build()`, `export()` and `runTask()` no
longer see plugin-injected tasks. Callers: the VS Code "Validate" command
(`packages/vscode/src/commands.js:39`, via the worker) and MCP
`kirigami_validate`.

**Fix:** Validate into a local variable and leave `#config` untouched, or mark
the project unloaded so the next operation reloads.

### N3 — P2: Duplicate task names are accepted silently

**Reproduced.** With a kirigami.yaml task `dup` and a plugin injecting another
task named `dup`, both end up in `config.tasks`. `build()` runs both, and
`runTask('dup')` silently picks the project's. Nothing reports the collision,
unlike the task-type and command registries, which reject duplicates.

**Fix:** Reject duplicate task names in `validateConfiguredTasks()`, naming
the source (project or plugin) when possible.

### N4 — P3: Export path overrides and banners mutate the loaded config

**Reproduced.** `export({ path })` writes the override into
`config.export.path` (`packages/kirigami/index.js:159`). A later `export()`
without arguments reuses it: `out-custom` was used twice. The export loop also
assigns `task.banner` onto the `config.tasks` objects themselves. MCP hides
this by reloading before each export; direct API and long-lived embedders do
not.

**Fix:** Compute the destination and per-run task copies locally, without
writing to the config.

### N5 — P3: Scripts from linked or workspace plugins fail containment

**Confirmed by code; not reproduced.** `projectFile()` in
`packages/php-prepros/src/prepros.js:269` requires the *real path* of every
PHP file to be inside the project. A `scripts:register` entry points at the
plugin's own `.php` file. For a plugin installed with `npm link`, from a
workspace, or through `resolvePlugin()`'s fallback to kiri's own resolution,
that real path is outside the project. The script is then rejected with
"PHP file outside project". The regression fixture only covers a plugin
physically inside `node_modules`.

**Fix:** Decide the trust contract. Either explicitly allow resolved plugin
package directories as mount sources, or document that plugin scripts require
a regular install.

## Hygiene and conventions

- Stray tracked files: `phpinfo.html` (70 kB) and `PR-LICENSE-SEPARATION.md`
  (a PR description) at the repository root.
- Dead code published in packages: `packages/kirigami/bin/tasks/conf.js` is an
  empty file listed in the core tarball. `packages/cli/bin/cmd/test.js` is
  debug scaffolding.
- French remains in 13 tracked source files, despite the English-in-repo
  convention. It includes recent additions in `packages/mcp/index.js` (the
  "À ajouter…" TODO at line 265 and five "pas besoin de reloader" comments),
  and a French note in `docs/BUGS.md`.
- `docs/BUGS.md`'s audit intro still says "the remaining code findings are
  open" although A07–A14 are listed as fixed right below.
- `packages/sdk/README.md:147` has a garbled `TASKS_REGISTER` description.
- `refactor/core-api` is 68 commits ahead of `main` and unmerged; long-lived
  divergence raises the merge and release risk.
- `node:sqlite` is used (4 call sites). Its experimental-warning status under
  the Node 24 floor was not verified.

## Suggested correction order

1. N1: make export refuse to empty directories it did not create.
2. N2 and N3: small, self-contained fixes; add regression tests next to
   `plugin-task-injection.test.js`.
3. Remove `php.js.bak` from Git and tighten the php-wasm `files` allowlist (A17).
4. N4, then decide N5's trust contract.
5. Add a root `npm test` and a CI matrix covering Node 24/26 on Windows and
   Linux (A16); remove the placeholder test scripts.
6. Hygiene pass: stray files, dead modules, remaining French comments.
